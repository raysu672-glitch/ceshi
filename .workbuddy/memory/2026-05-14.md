## Bug 修复：注册密钥验证失败

- **问题**: 学生注册输入激活密钥时始终显示"无效的激活密钥"
- **现象**: 管理端生成密钥成功（Supabase 有记录），但注册端验证失败
- **根因**: `index.html` 从未调用 `tracker.init()` 传入 Supabase URL/Key，导致 `validateKey()` 内部 `_supabaseUrl` 为空，直接降级到 localStorage 查询——密钥在 Supabase 里，localStorage 里没有
- **修复**: 在 `index.html` 初始化段添加 `tracker.init({ module: 'platform', supabaseUrl, supabaseAnonKey })`
- **commit**: `7a9fc7f`

## Bug 修复：学生ID共享 + 管理端只显示一个学生

- **问题 1**: 同一浏览器注册多个学生共享同一 `student_id`
  - 111 注册 → `stu_abc123`，退出后 112 注册 → 还是 `stu_abc123`
  - `handleLogout()` 只清了 name，没清 student_id
  - `_registerStudent()` 用 `merge-duplicates` 直接覆盖了 111 的数据
- **问题 2**: 管理端 RPC 从 `practice_events` 出发查询，没有练习数据的学生不显示
- **问题 3**: RLS 策略过严，`practice_events` 只允许查自己的事件
- **修复**:
  - tracker.js: `logout()` 清除 `STUDENT_ID_KEY`；添加 name→id 映射存储
  - tracker.js: 新增 `registerNewStudent()` 和 `loginAsStudent()`
  - index.html: 注册调用 `registerNewStudent()` 生成全新 ID
  - index.html: 登录调用 `loginAsStudent()` 恢复原 ID
  - schema.sql: RPC 从 `students` 表出发（LEFT JOIN practice_events），确保所有注册学生显示
  - schema.sql: 放宽 RLS 策略，students/practice_events/memory_states 允许匿名读写
- **commit**: `8b857ac`
