## 密钥生成失败修复（第二次，14:03）

### 问题
教师端"生成密钥"显示生成失败。

### 根因（双重）
1. **函数签名版本不匹配**：旧 schema DROP 语句只删了5参数旧版，若 Supabase 中存在旧签名函数，新签名找不到
2. **`RETURNS SETOF access_keys` 不兼容 PostgREST**：Supabase RPC 通过 PostgREST 调用时，`RETURNS SETOF <表名>` 无法正确序列化返回列，需改为 `RETURNS TABLE(...)`

### 修复内容
1. 新建 `supabase/patch_fix_generate_keys.sql` — 仅修复此函数的补丁SQL，可单独执行
2. 更新 `supabase/schema.sql` 和 `full_schema.sql`：
   - DROP 语句补全两种签名（5参数+6参数）
   - `batch_generate_keys` 改为 `RETURNS TABLE(id UUID, key TEXT, ...)` 明确列出所有返回字段
   - 函数体改为显式赋值每列后 `RETURN NEXT`

### 操作方法
在 Supabase SQL Editor 执行补丁文件 `supabase/patch_fix_generate_keys.sql`（无需重建所有表）

## 管理端 Bug 修复（15:30）

### 修复 1：SQL GROUP BY 错误
**根因**：`get_admin_students_profile` 函数主查询 `LEFT JOIN practice_events e` 后，SELECT 中混用了聚合函数（AVG/COUNT）和非聚合列（s.id 等），但没有 GROUP BY。

**修复**：把 behavior_type 的计算移到 `student_module_stats` CTE 中，主查询不再 JOIN practice_events，也不需要 GROUP BY。

### 修复 2：tracker.js 缺少 getAdminMemoryOverview
**根因**：`admin/index.html` 的 `loadMemory()` 调用了 `adminTracker.getAdminMemoryOverview()`，但 `tracker.js` 中没有这个方法。

**修复**：在 `tracker.js` 中添加 `getAdminMemoryOverview()` 方法，调用 `get_admin_memory_overview` RPC，并加入公开 API 导出列表。
